# 教學影片／招生影片／OSCE 示範影片：腳本上傳、角色對齊、場景設定、分段審核

中文 | 這份流程只在 Colab Notebook（`AI_Movie_Maker_Colab.ipynb`）裡使用。

## 1. 腳本上傳（`mvkit/script_import.py`）

直接上傳你平常寫的腳本，不用先改成表格。可用格式：

| 格式 | 說明 |
| --- | --- |
| `.txt` / `.md` | 「分鏡 1：標題」開頭，下面寫 `場景：` `畫面：` `對話/口白：` `動作與評分重點：`（也接受 `鏡頭 1`、`Shot 1:`、`運鏡：` `角色：` `秒數：` `字幕：`） |
| `.docx` | 同樣的寫法存成 Word 檔，不需要另外安裝套件 |
| AI Studio 匯出檔 | `{"veoPrompt": {"prompt": "..."}}` 會自動取出腳本文字 |
| Markdown 分鏡表格、分鏡 `.json`、`project.py` | 照舊走原本的讀取方式 |

範例：[`examples/osce_demo/script.txt`](../../examples/osce_demo/script.txt)

- `第一幕：…` 會記在每一鏡的備註；`動作與評分重點` 也進備註，並出現在審核表。
- `（口述）「…」`、`（對病人）「…」`：引號裡是台詞，括號裡是誰在說／對誰說（見第 2 節）。
- 沒寫秒數時，依台詞長度估算（台灣華語約每秒 4 字，加 1.6 秒前後留白），最短 5 秒。
- 一句台詞超過單鏡上限（14.65 秒）會在句號處自動切成 `03a`、`03b`…，畫面描述相同，後一鏡接前一鏡尾幀。

## 2. 角色對齊（角色表）

角色表寫一次，整支影片共用：

| 欄位 | 用途 |
| --- | --- |
| 代號 | 程式內部用的 id，例如 `examinee` |
| 名稱 | 寫進 Prompt 的稱呼（建議英文，例如 `examinee doctor`） |
| 別名 | 腳本裡出現的叫法：`考生, 醫師`、`病人, 王先生`。用來自動判斷這一鏡有誰 |
| 外觀 | 固定的長相與服裝文字，每一鏡都一樣 |
| 參考圖 | 角色圖檔名（Step 2 上傳），固定送進 `<Picture 2..>` |
| 位置 | 固定站位（例如 `left of the bed`），避免左右互換 |
| 聲音 | 固定的聲音描述，`native_h3_audio` 時每鏡都寫進 Prompt，聲音才不會換人 |
| 主講 | 填「是」：`（口述）`、`（對病人）` 這類台詞由他說（沒填就用第一位） |

對齊規則：

- 每一鏡的角色 = 腳本「角色」欄 ＋ 文字提到的名稱/別名 ＋ 說話者與說話對象 ＋ 場景的常駐角色。
- 角色永遠依角色表順序排列，所以同一個人在每一鏡都是同一個 `<Picture n>`。
- 說話者：`（病人）` → 病人；`（對病人）`／`（口述）` → 主講者；`（旁白）`／`（畫外音）` → 畫外旁白。說話者有參考圖時，Prompt 會寫成「The person in `<Picture 2>` … says」，讓嘴型對在正確的人臉上。

## 3. 場景設定（場景表）

| 欄位 | 用途 |
| --- | --- |
| 代號／名稱／別名 | 腳本的 `場景：病床旁的操作台` 會用別名對到場景 |
| 描述 | 空間配置、光線、主要道具，每一鏡都一樣 |
| 參考圖 | 場景基準圖（`<Picture 1>`）。實際技能教室照片最穩 |
| 角色 | 這個場景常駐的角色代號，例如 `examinee, patient` |

- `場景：特寫上臂`、`特寫聽診與回抽` 這種只寫鏡頭大小的，不會變成新場景：留在包含這一鏡所有角色的場景（優先沿用上一鏡），「特寫…」移到運鏡欄。
- 只有一個場景時，所有對不到的場景文字都併入那個場景，並把原文寫進畫面描述。
- 範例：[`examples/osce_demo/bible.md`](../../examples/osce_demo/bible.md)

Step 3 會印出**對齊報告**：每鏡的場景、角色（`<Picture 2..>` 順序）、說話者、實際會送出的參考圖，以及缺圖、對不到別名等提醒。**缺場景圖的段落在 Step 4 下載模型之前就會停下**，不會浪費 GPU。

## 4. 每次 2 分鐘、確認後再繼續（`mvkit/batches.py`）

1. `BATCH_MINUTES`（預設 2）把分鏡切成連續段落；段落快滿時若剛好換場景，就在換場景處切，不會把一場戲切兩半。
2. Step 4 只生成「下一段」，做出預覽影片（同樣的單一聲軌與字幕處理）、抽幀檢視圖、審核表（每鏡的台詞與評分重點）。
3. Step 5：
   - `approve`：這一段通過，Step 4 才會往下一段。
   - `redo_shots`：只重拍填入的鏡號，自動換 seed（同 seed 同 Prompt 會生出一樣的畫面），舊片段移到 `raw_clips/_rejected/`。被重拍鏡頭後面接尾幀的鏡頭會列出來，勾 `REDO_CHAINED_SHOTS_TOO` 一起重拍。
4. 改了腳本某一鏡的文字、角色表或場景表，重跑 Step 3，**只有受影響的鏡頭**會重新生成，已確認的狀態也會自動取消。
5. 全部段落確認後，Step 6 合成全片（不需要 GPU）。

審核紀錄存在工作資料夾的 `outputs/<專案>/review_state.json`，片段進度在 `progress.json`，整個專案快照在 `project.json`。

## 5. 省 Colab 運算單元

- 工作資料夾預設放在 Google Drive（`USE_DRIVE_WORKSPACE`）。模型仍裝在 Colab 本機。
- Step 1–3、5、6 可以用 CPU 執行階段：先把腳本、對齊、分段、Prompt 看到滿意，再切 GPU 跑 Step 4。
- 審核期間 GPU 照樣計費：勾 `AUTO_DISCONNECT_AFTER_BATCH`，生成完就自動中斷；回來後跑 Step 1 → 3 → 5 接續（`SCRIPT_SOURCE = reuse_last`）。
- 填 `COMPUTE_UNITS_PER_HOUR`（Colab「資源」面板上的數字），Step 4 會用實測速度估算這一段與剩下全部要多少運算單元。

## 6. 三種用途預設（`USE_CASE_PRESET`）

| 預設 | 畫面 | 連貫模式 |
| --- | --- | --- |
| `osce_demo` | OSCE 考場、均勻光、手部與器械清楚、步驟慢而正確；負面提示加上「不正確的臨床技術」 | `hybrid` |
| `teaching` | 明亮柔光、乾淨背景、穩定中景 | `hybrid` |
| `recruitment` | 暖色調、淺景深、緩慢運鏡 | `anchor`（場景多，每鏡從場景圖起始） |

## 7. 審核時要特別看的

AI 影片可能把臨床步驟做錯（手套、無菌、器械握法、解剖位置）或手指變形。OSCE 示範影片請由熟悉該技能的老師逐鏡對照審核表的評分重點；不正確的鏡頭寧可重拍或改成旁白＋實拍插入，不要放進教材。真人照片作為角色圖前，請取得當事人同意。
