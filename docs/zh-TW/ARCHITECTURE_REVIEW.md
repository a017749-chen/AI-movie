# 架構檢視與重新設計（0.9.0）

中文 | 針對實際跑了三次都出現的兩個問題：**人物重複出現**、**配音對不上**。

## 1. 整體流程（不變的部分）

```
你寫好的腳本 (.txt/.md/.docx)        角色／場景設定表 (bible.md)        參考圖（場景空景、角色單人照）
          │                                   │                                 │
          └──────────────► Step 3（CPU）：解析 → 對齊 → 每個分鏡決定「誰入鏡、誰說話」 ◄────┘
                                   │   參考圖檢查、生成計畫表、整批 Prompt 預覽
                                   ▼
                 Step 4（GPU）：只生成下一批（≤ 2 分鐘）── Colab 上的 ComfyUI + MiniMax H3
                                   │   Ref2VA（參考圖）／FL2VA（首幀、首尾幀）
                                   ▼
                 預覽影片 + 抽幀檢視圖 + 自動檢查（台詞／說話時間／臉數）+ 審核表
                                   │
                 Step 5：你審核 → approve 才能生成下一批；redo_shots 只重拍指定段落
                                   ▼
                 Step 6（CPU）：全部確認後合成全片（單一聲軌、繁中字幕）
```

「一段 = 一支 H3 影片（10 或 15 秒，段內切鏡）」「每批 2 分鐘、確認後才繼續」「腳本可上傳」這些設計是對的，保留。
這次重寫的是**決定誰入鏡、誰說話的那一層**和**後製接片**。

## 2. 人物重複出現：找到的原因

| # | 原因（舊版） | 為什麼會重複 | 新版做法 |
| --- | --- | --- | --- |
| 1 | 對齊時把**場景的全部常駐角色**加進每一段 | 特寫手部的段落也送了考生＋病人兩張角色圖。H3 Ref2VA 傾向把參考圖裡的每個人都畫出來 → 多出人、同一人出現兩次 | 每個**分鏡**判斷誰入鏡；只有入鏡的人送參考圖。腳本可用 `出場：` 直接指定 |
| 2 | 同場景接上一段尾幀（`hybrid`）時，尾幀當 `<Picture 1>`，同一批人的角色圖又當 `<Picture 2..>` | 同一個人在兩張圖裡各出現一次，Prompt 沒說是同一人 → 畫成兩個人 | 預設改 `anchor`（每段從同一組場景＋角色圖出發，也不累積誤差）；選用接續時，Prompt 明寫「`<Picture 1>` 裡的人就是角色圖裡的人，不是另外的人」 |
| 3 | 主角的**三視圖**當「其他參考圖」送出 | 三視圖裡有三個同一人 → 生出雙胞胎、三胞胎 | 預設不送（`SEND_EXTRA_VIEWS=False`）；Step 3 檢查角色圖是否橫幅／多張臉 |
| 4 | 場景圖預設當**第一格**（全景開場時 "fully referenced at 0.00 s"） | 空景當第一格，人物要憑空出現；場景照片裡若有人，又會和角色圖的人疊在一起 | 場景圖只當「地點參考，不要複製裡面的人」；只有尾幀與首幀圖才當第一格（`SCENE_AS_OPENING` 可改回） |
| 5 | Prompt 沒有人數 | 模型不知道畫面上應該有幾個人 | 每段開頭寫「畫面上剛好 N 人：`<Picture 2>`…、`<Picture 3>`…，每人只出現一次，沒有雙胞胎、分身、路人」；每個分鏡再寫 `On screen: …; nobody else.` |

## 3. 配音對不上：找到的原因

| # | 原因（舊版） | 影響 | 新版做法 |
| --- | --- | --- | --- |
| 1 | **後製接片會漂移**：每段先各自轉成 AAC 再串接，AAC 的前置取樣與補齊讓每段聲音提早約 **60 ms** | 實測 12 段（2 分鐘）後聲音比嘴型早 **0.66 秒**，越後面越對不上（人眼約 45 ms 就看得出來） | 每段精準裁成 N 個影格、N×2000 個取樣點（48 kHz／24 fps）的 PCM，接好後才編一次 AAC。實測 12 段全部誤差 +3 ms（量測解析度），已加進測試 |
| 2 | 特寫手部時的 `（口述）` 被寫成「`<Picture 2>` 這個人說…」 | 模型為了對嘴硬把臉塞進手部特寫（又多一個人），或嘴型對在錯的人臉上 | 特寫手部／器械（沒寫臉部動作）自動改成**畫外音**：「考生的畫外音（臉不在畫面上）…畫面上沒有人動嘴」。`（考生畫外）`、`（考生OS）` 也可直接標 |
| 3 | 畫面上的說話者沒限制其他人 | 兩人同框時嘴型跑到另一個人臉上 | 「只有這個人的嘴動，其他人閉嘴」；沒台詞的分鏡寫「所有人閉嘴」 |
| 4 | 生成後只能靠人工看 | 台詞說錯、說到別的分鏡、多出人聲都要逐支聽 | 新增**自動檢查**：faster-whisper（CPU）逐分鏡比對「該分鏡時間內聽到的話」和腳本台詞（相似度、時間錯位、多出人聲、說到被裁掉的結尾），結果列在審核表最上面 |

> H3 原生語音每支影片都是重新生成的聲音，即使每段寫一樣的聲音描述，音色仍可能小幅變化；這是模型本身的限制。
> 若需要完全一致的聲音，可用 `clip_voiceover`（外部錄音／TTS 取代 H3 聲音），但嘴型就不會對齊台詞。

## 4. 新的「誰入鏡、誰說話」規則

每個分鏡依序判斷：

1. 有寫 `出場：考生、病人` → 就是這些人（`出場：無` = 空景）。
2. 沒寫 → `畫面描述` 裡提到的人 ＋ 說話者（特寫手部或標了畫外時除外）＋ 被說話的對象（`（對病人）`，特寫除外）。
3. 遠景／全景都沒提到任何人 → 段落的 `角色：`，再沒有才用場景表的常駐角色。
4. 說話者不在入鏡名單、標了 `畫外`、或是特寫手部 → 畫外音。

整段的參考圖 = 所有分鏡入鏡者的聯集（依角色表順序）。Step 3 會印出每段的「生成計畫」：

```
■ 段落 02｜參考圖｜10.0 秒｜場景 bedside
   參考圖：<Picture 1>=scene_bedside.png  <Picture 2>=char_examinee.png  <Picture 3>=char_patient.png
     2-1 中景  3.0s  入鏡：考生、病人  說話：考生 「我先幫您把袖子捲起來。」
     2-2 特寫  4.0s  入鏡：考生        說話：考生（畫外） 「壓脈帶下緣在肘窩上兩到三公分。」
     2-3 近景  3.0s  入鏡：考生、病人  說話：考生 「手臂放輕鬆就好。」
```

**在花 GPU 之前**看這張表：入鏡或說話者不對，就在該分鏡加 `出場：` 或把台詞標成 `（考生畫外）`，重跑 Step 3。

## 5. 參考圖規則（Step 3 會自動檢查）

- **角色圖**：一個人、正面、單一角度、直幅半身、素色背景、短邊 ≥ 768 px。不要三視圖、不要合照。
- **場景圖**：**沒有人**的空景（實際教室照片最穩）。
- 不同角色不要共用同一張圖。
- 檢查項目：橫幅（像三視圖）、角色圖臉數 ≠ 1、場景圖有人、圖太小、多個角色共用一張圖。

## 6. 模組對照

| 模組 | 職責 | 這次的變更 |
| --- | --- | --- |
| `segment_script.py` / `script_import.py` | 讀你寫好的腳本 | 新增分鏡欄位 `出場：`（也接受 `入鏡：`、`畫面人物：`），可寫「同上」 |
| `alignment.py` | 角色／場景對齊 | 改為逐分鏡決定入鏡者與畫外音；不再把場景全部角色塞進每段；`（考生畫外）`／`（考生OS）` |
| `script_loader.py` | H3 Prompt | 人數、每分鏡入鏡、畫外音、只有說話者動嘴、尾幀身分對應；場景圖預設只當地點參考；三視圖預設不送 |
| `h3_colab_runner.py` | ComfyUI 圖、呼叫 H3 | 不變（Ref2VA／FL2VA 節點與模型選擇照舊） |
| `colab_pipeline.py` | 後製 | 每段精準到影格與取樣點的 PCM 中間檔，接片不再漂移 |
| `qc_review.py`（新） | 自動檢查 | 參考圖檢查、逐分鏡台詞與時間比對、人臉數量 |
| `batches.py` | 每批 2 分鐘、審核閘門 | 生成計畫表、整批 Prompt 預覽、審核表列出入鏡／說話者（畫內／畫外）與自動檢查結果 |
| `presets.py` | 用途預設 | 連貫模式預設 `anchor` |

## 7. 升級注意

- 提示詞變了，指紋也跟著變：之前生成的片段會被視為「腳本已修改」而重新生成。建議開新的 `PROJECT_TITLE` 或清空 `outputs/<專案>/draft` 重跑。
- 想回到舊行為：`CONTINUITY_MODE=hybrid`（接尾幀）、`SEND_EXTRA_VIEWS=True`（送三視圖）、`SCENE_AS_OPENING=True`（場景圖當第一格）。
- 這些改動在 CPU 上都有測試（Prompt 內容、入鏡判斷、接片同步、自動檢查邏輯），但 H3 實際畫出來的效果仍要用 GPU 跑過第一批確認。
